# CHANGELOG 追記

書き方の規約は `CHANGELOG.md` の冒頭 (最初のバージョン見出しより前) にある。追記の前に必ず読み、そこに従う。ここには手順だけを置く。

## 手順

1. 変更を把握する
   - `git fetch origin develop` のうえ `git log origin/develop..HEAD` と `git diff origin/develop...HEAD`、未コミットの `git diff HEAD` を見る
   - 引数で対象 (コミット・ファイル・説明) が渡されたときは、それに絞る
2. 利用者に影響するかを判断する
   - 冒頭の規約で「書かない」とされる変更 (テスト・リファクタリング・ビルド用スクリプト・ドキュメント整理・依存更新など) だけなら、追記せずに理由を報告して終える
   - 影響の有無を判断できないときは、作業を止めてユーザーに確認する
3. 既存の `[Unreleased]` 節と重複していないか確かめる。同じ変更の項目があれば、新しく足さずにその項目を直す
4. 節を選んで追記する
   - 節は冒頭の表から選ぶ。`[Unreleased]` に無い節は、表の順序を守って見出し (`### Added` など) を作る
   - ユーザー設定 (`Settings.settings` / `user.config`) の引き継ぎ・初期化に関わるときは **Settings**、互換性を壊すときは **Breaking changes** にも書く
5. 書いた項目を報告する (PR 本文にそのまま使える形で)

## 注意

- `scripts/build-user-docs.ps1` が `CHANGELOG.md` を利用者向けドキュメントの変更履歴ページに変換する。`## [Unreleased]` とその下の `###` 見出しの構造を崩さない。既存のバージョン節は編集しない
- リンクは外部 URL・`docs/user/*.md`・`CHANGELOG.md` 内のアンカーだけにする (それ以外の相対リンクは変換時に外れる)
- 追記は、対応するコード変更と同じコミットに含める。コミットはユーザーの指示があるまでしない
